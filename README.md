# 任务花销（dsh-task-cost）

给 DeepSeek Harness 的对话框加一个「¥ 任务花销」入口，点开是浮动小屏，六项数据（单位：元）：

| 项 | 什么时候有值 |
| --- | --- |
| 该任务预计花费 | 布置任务、估算完成后 |
| 预估误差 | 同上，形如 `-1.50 / +1.50` |
| 实际花费 | 任务完成（真实扣费）或取消（¥0.00）后 |
| 余额 | 始终显示；直接读 DeepSeek 账号余额 |
| 预算 | 无任务时可填，布置任务前保存 |
| 预算误差 | 同上，表示预算上下浮动 |

没有任务的会话里，除了余额、预算、预算误差，其余都是横杠。

## 行为

1. 你在输入框里发出一条任务（不是 `/` 命令）。
2. Host 用 `tokenMeter` 取当前上下文 token，再按 prompt 的 CJK 字数、代码块、动词强度估出步数与单步输出 token，
   得到 `总输入 ≈ 步数 × (上下文 + prompt) + 步数²/2 × 单步输出 × 0.7`、`总输出 ≈ 步数 × 单步输出`。
3. 按 `prices.json` 的模型单价换钱，给出中心值 + 波动区间；历史真实花费会做 32% 的校准。
4. 估算一出来，小屏自动弹出。
5. 估算区间完全落在 `[预算-预算误差, 预算+预算误差]` 内 → 记 `auto`，不打断你；
   超出 → 小屏自动打开并给出方案（按花费从小到大：按当前模型跑完 / 节省模式 / 换低价模型），
   你选「仍按超预算执行」「改用节省方案」或「取消任务」。
6. 任务结束：`completed` 显示真实扣费；`aborted/interrupted` 或你点了取消 → 显示 ¥0.00。

## 数据与接口

- Host 路由（同源）：`GET /task-cost/state?sessionId=…`、`POST /task-cost/budget`、`POST /task-cost/decision`、`GET /task-cost/status`
- 状态落盘：`<DSH_PROFILE_DIR>/data/task-cost-state.json`（按会话记预算与任务，保留 7 天/60 个会话）
- 价格表：包内 `prices.json`，改完下一次估算就生效

## 估算口径的限制

这是**估算**，不是账单：真实花费以每个 `assistant/message` 的 usage 累加为准。
如果某个 provider 不回 usage，实际花费会偏低。

## 自测记录（真跑过）

- 子会话任务「统计文件行数」：预估 ¥0.0792（区间 0.0395~0.1308），实际 ¥0.0848，模型 deepseek-v4-pro。
- 给同一会话设预算 ¥0.02 ± ¥0.01，再布置一个任务：预估中心 ¥0.2581、区间 0.1316~0.4225 → `needsDecision: true`，
  三档方案（按当前模型 / 节省模式 / 换低价模型）都标了 `within: false`，符合"优先预算内方案"的排序逻辑。
- 余额接口读到真实账号余额（如 ¥7.08），小屏每 1.5 秒刷新，随账户变动。

排障看 `GET /task-cost/status` 的 `events`：`counts` 是收到的会话事件计数，
`startLog` 记录每次「估算启动」的 sessionId / 有没有拿到 prompt / prompt 长度，`lastError` 是最近一次事件处理异常。
